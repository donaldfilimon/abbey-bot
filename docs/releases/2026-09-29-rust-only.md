## Operator boundary

The scheduler uses existing explicit scope opt-in, time zones, quiet hours, and daily ceilings. It rechecks origin access and project authority, resolves private recipients separately, and requires a bounded complete guild-member enumeration before shared text-channel delivery. A missing privileged member-list capability, unsupported channel type, or incomplete audience proof suppresses shared delivery. No intent, permission, provider, or model is enabled implicitly.

An attempt is durably reserved before the send. Failed, cancelled, timed-out, or interrupted attempts retain coverage and become `ReviewRequired`. The policy intentionally prefers a missed delivery to an automatic duplicate after an ambiguous network outcome. This is not exactly-once delivery; operator review is required. Failed settlement persistence leaves the durable attempt recoverable on restart.

The generic external-action contract and future work-recall admission/briefing integration remain staged surfaces, not claims of newly deployed integrations. Existing memory confirmation and server-action authorization remain the executable paths. No public commands or persistence format were added.

Provider qualification, installed-artifact identity, live Discord isolation, managed deployment, and human-witnessed voice remain separate operator acceptance. Linux and Windows runtime acceptance is unverified on this macOS host. Hosted billing-refused checks and ignored live tests are exclusions, never passes.

Final release evidence is produced outside the source tree after the published main SHA passes the self-hosted gate. It includes the source SHA, toolchain, locked dependency/contract revisions, archive digest, binary checksum, CI link and explicit exclusions.
